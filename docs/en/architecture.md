```
│  report.rs     Markdown / HTML / JSON exporters, bilingual                       │

│  safety.rs     confirmation nonces + path containment                            │

```

## Design decisions

- **The rule catalog is data, not code.** `src-tauri/resources/rules.json`
  (generated by `tools/gen_rules.py`, validated by `tools/check_rules.py`) holds
  every rule: engine, severity, confidence, path globs, regexes (Rust-`regex`
  compatible — no lookaround), negatives, and bilingual EN/FA title,
  description and remediation. Adding a rule needs no Rust changes.
- **Heuristics complement regexes.** Contextual detectors (typosquat distance,
  lockfile drift, removed assertions, zero-width characters, `pull_request_target`
  + checkout, …) live in `engines/heuristics.rs` and are referenced from the
  catalog by `heuristic` name, so they stay toggleable per engine.
- **Localization is split cleanly.** App chrome strings live in the frontend
  dictionaries; rule knowledge lives in the catalog. Findings therefore carry
  both languages and the UI can switch language without rescanning; exporters
  pick one language per report.
- **Scans run off the async runtime.** `start_scan` spawns a blocking task; the
  UI tracks it through events and can cancel via an `AtomicBool` per scan id.
- **No OpenSSL, no cmake.** `git2` is used with `default-features = false` +
  `vendored-libgit2`, so Windows builds need only MSVC.
- **Deterministic scoring.** Severity weights × confidence, capped at 100, with
  documented bands and verdicts (see user guide).

## Testing

- Rust unit tests: catalog loading, glob behaviour, masking, entropy, ids
  (`cargo test` in `src-tauri`).
- CI runs frontend typecheck + build, `cargo check` on Ubuntu and Windows,
  `cargo test` and clippy (advisory), plus catalog regeneration/validation.
- Release builds run on `windows-latest` and upload NSIS/MSI/portable artifacts;
  tagged pushes additionally create a GitHub Release with those binaries.
